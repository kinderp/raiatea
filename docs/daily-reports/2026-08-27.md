### PDF1c findings risolti

#### PDF1C-F1 — body/picture/caption evidence ambiguity

Risolto con:
- explicit `body_order_index` / `body_order_source`;
- `picture_collection_state = present|unavailable|degraded`;
- caption blocks separati dal body order;
- explicit relation refs + consistency checks.

#### PDF1C-F2 — Provider failure exported before classification

Il primo runtime poteva chiamare `document.export_to_dict()` prima di
classificare un normale Docling failure result.

Risolto:
- status classificato prima dell'export;
- failed/restricted/unknown -> bounded attempt evidence;
- nessuna current representation fabbricata.

#### PDF1C-F3 — environment freeze scope troppo ampio

Il primo verifier confrontava anche package amministrativi fuori dal constraints
lock.

Risolto:
- il product verifier verifica solo il package-name set esplicitamente
  constrained;
- wheel, Docling version e model payload restano verificati separatamente.

#### PDF1C-F4 — semantic origin / heading level overclaim

Risolto:
- `title` / `section_header` possono essere mappati a normalized `heading`;
- numeric heading level solo da Docling `item.level` esplicito;
- normalized semantic role marcato `raiatea-aligned`;
- Provider text surface resta `provider-native`.

#### PDF1C-F5 — list-item visible surface loss

Docling lossless può esporre:

```text
orig = "1. First item"
text = "First item"
```

Risolto:
- per explicit `list_item`, non-empty `orig` è usato come Provider surface;
- gli altri label continuano a usare Docling `text`;
- nessuna typography inference aggiunta.
